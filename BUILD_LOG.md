## 2026-10-18: Task 4, mastery engine and data store (server side)
- What was done: tests first (the server tests failed because the code did not exist), then the code until all passed.
  - Store: Node's built-in SQLite (node:sqlite, no new dependency), WAL mode, transactions, all SQL in one file. Tables as specified, pseudonymous only (no name column; student codes must look like 8B-17). Database rules make the risky things impossible even when requests race: a proof question is single-use for everyone (unique index), each item takes one answer, each teach try number is used once, and a student has at most one open proof per skill.
  - Mastery engine (the only writer of mastery): LOCKED → OPEN → KEY1 → MASTERED, plus NOT_YET after a failed proof (KEY1 kept, PROOF_COOLDOWN_HOURS, default 24, 0 allowed). It never trusts stored "correct" flags: it re-creates every question from its seed and re-checks the child's own answers and typed lines with src/core. Every write stores evidence ids and the skill version, and logs a mastery_changed event.
  - Services: practice, teach, proof (AI off, 3 solve + 1 apply, 30 minutes), stuck board (most frequent mistake per student, last 7 days), anonymous pilot CSV (marked "small sample" under 30 students). Unknown wrong answers are counted for the Misconception Miner. Every action logs an event.
  - Small addition to src/core: parseAnswer() reads a typed answer ("5", "−7/2", "x = 5"), written test-first.
- Choices made: teach questions are stored as items of kind 'teach' (with the Shishya's mistake id); items have a 'format' (solve/apply) and a 'runId' (teach session or proof run). An abandoned proof is closed as failed when the next proof is requested. A new skill version sends KEY1 / NOT_YET back to OPEN.
- Tests: 147 passing (38 new). They cover the whole state table, forged "correct" rows being ignored, racing answers and proof starts from two database connections, cooldown, the 30-minute limit, the stuck board, the CSV having no codes, no name columns, and a source scan proving only mastery.ts writes mastery (checked against a deliberately bad file).
