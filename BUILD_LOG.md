## 2026-10-18: Task 4, mastery engine and data store (server side)
- What was done: tests first (the server tests failed because the code did not exist), then the code until all passed.
  - Store: Node's built-in SQLite (node:sqlite, no new dependency), WAL mode, transactions, all SQL in one file. Tables as specified, pseudonymous only (no name column; student codes must look like 8B-17). Database rules make the risky things impossible even when requests race: a proof question is single-use for everyone (unique index), each item takes one answer, each teach try number is used once, and a student has at most one open proof per skill.

- Choices made: teach questions are stored as items of kind 'teach' (with the Shishya's mistake id); items have a 'format' (solve/apply) and a 'runId' (teach session or proof run). An abandoned proof is closed as failed when the next proof is requested. A new skill version sends KEY1 / NOT_YET back to OPEN.

## 2026-10-18: Task 8, store on libSQL (local file and Turso) for Vercel
- Why: Vercel's servers do not keep files between requests, so a SQLite file there would lose all data. libSQL is SQLite-compatible and works both as a local file (laptop, demo) and as Turso's free hosted database (cloud).
- What was done: replaced node:sqlite with `@libsql/client` (the one new dependency, approved by Das) inside `src/server/store.ts` only; all SQL stays there. Config from `DATABASE_URL` (default `file:data/shishya.db`, demo `file:data/demo.db`) and `DATABASE_AUTH_TOKEN` (Turso only). The store, mastery engine, services, server actions, pages and seed script are now async. Schema creation runs at start-up (idempotent). All rules kept: transactions (BEGIN IMMEDIATE), the unique index on proof questions, one answer per item, one open proof per skill, and only mastery.ts writes mastery.
- One design point: local libSQL connections are synchronous, so two connections in one process writing at once could block the whole server. Writes in one process now take turns (a small lock per database), and transactions run in a context so nested calls join the open transaction. The race tests are now real races (`Promise.all`), including a new same-connection race; they passed 5 runs in a row.
- Vercel readiness: no local-disk writes in production (DATABASE_URL and SESSION_SECRET are required there; local folders are only created for `file:` URLs). Added `.env.example` (names only, no values; `.env.local` stays ignored) and a "Deploy to Vercel" section in README.md. The production build was started on a copy of the demo data and served logged-in student and teacher pages and the CSV without errors.
- Windows note: libSQL keeps a database file open until the process ends, so tests clean up old temporary folders on the next run.
- Tests: 194 passing (3 new for the database configuration, 1 new race test). Lint clean, build passes.
- Files: `package.json`, `package-lock.json`, `src/server/{store,mastery,services,instance}.ts`, `src/server/__tests__/*`, `src/app/actions.ts`, `src/app/_lib/{auth.ts,student-pages.tsx}`, `src/app/s/home/page.tsx`, `src/app/teacher/[class]/{page.tsx,export/route.ts,project/page.tsx}`, `scripts/{seed-demo.ts,dev-demo.mjs}`, `.env.example`, `.gitignore`, `README.md`, `BUILD_LOG.md`.

## 2026-10-18: Task 6, free AI client and the Misconception Miner
- AI client (`src/agents/llm.ts`, plain fetch, no new dependency): any OpenAI-compatible /chat/completions endpoint with tool calling. Providers in order from `LLM_PROVIDERS` (default groq, then openrouter with a ":free" model only); on an error or rate limit (429) it tries the next; a clear message if no key. Daily cap per provider (default 200). Every call is logged (provider, model, tokens, time, ok) to `data/agent-runs.jsonl` locally or stdout in the cloud; keys and message text are never logged.
- Agent loop (`src/agents/loop.ts`, ~50 lines): send messages + tools → run the tool the model asks for → add the result → repeat; stops at a final answer, at maxTurns, or when a tool ends the run. Tested with a FAKE model.
- Safety design: a mined mistake is JSON DATA (id, labels, stepType, firstWrongLine, line templates, answerFormula), never code. `src/core/minedMistake.ts` has our own tiny exact-fraction evaluator (a, b, c, d, whole numbers, + − × ÷, brackets; no eval) and a validator: allowed symbols only; reproduces ≥ 3 logged unknown answers; on 1,000 generated questions never the correct answer, never ÷ 0, not a copy of an existing mistake (same answer on < 10% of questions), last line "x = <answerFormula>", first wrong line really wrong.
- Miner (`src/agents/miner.ts`, `npm run miner -- alg.linear.both-sides [--fake]`): tools get_unknown_errors (anonymous a, b, c, d + wrong answer + count), validate_mined_mistake, submit_draft (only the exact JSON that just passed; validated again). Max 12 turns, 5 validations. Saves status DRAFT_TESTED. It reaches the database only through `src/server/miner-ports.ts`; a test scans `src/agents` for any import of student/session/server data.
- Teacher review: drafts appear on /teacher/[class] with label, child label, formula, how many wrong answers they explain and an example trace; Approve re-runs the validator. Approved mistakes join the skill (diagnosis, Teach traces, stuck board, projector). Mastery code is unchanged and never reads AI output.
- Store: mined statuses DRAFT_TESTED / APPROVED / REJECTED, with an automatic migration for older databases (demo.db migrated).

Lint clean, build passes.
